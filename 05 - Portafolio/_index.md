# ⭐ Portafolio

Trabajo propio que demuestra tus habilidades: scripts, proyectos, reportes y contenido técnico. **Esto es lo que muestras en una entrevista o en LinkedIn.**

## Estructura

| Carpeta | Qué va aquí | Ejemplo |
|---------|-------------|---------|
| `Proyectos/` | Proyectos completos con README y alcance definido | "Automatización de reconocimiento con Python" |
| `Scripts/` | Scripts individuales reutilizables | `autoenum.sh`, `parserscanner.py` |
| `Informes/` | Reportes de pentest ficticios (redactados como los reales) | "Informe de auditoría — Empresa X" |
| `Blog/` | Artículos técnicos, guías, walkthroughs | "Cómo pivoteé en HTB Box X — Guía paso a paso" |

## Cómo usar esta sección

- **Proyectos**: Cada proyecto es una nota que describe el problema, la solución, tecnologías usadas y resultados. Si el proyecto tiene código, considera crear un repo aparte y enlazarlo.
- **Scripts**: Cada script tiene su nota explicando qué hace, cómo usarlo y en qué contexto sirve. Adjunta el código o enlaza un Gist/repo.
- **Informes**: Reportes estilo "Executive Summary" + "Technical Findings" basados en máquinas de [[04 - Labs y Practica/_index|Labs]]. Es práctica para el mundo real.
- **Blog**: Artículos que podrías publicar en Dev.to, Medium o LinkedIn. Explica una técnica, un concepto difícil, o un writeup detallado.

## Qué conviene tener acá (priorizado)

- [ ] **1 script útil** — algo que hayas creado para automatizar una tarea
- [ ] **1 informe de pentest** — basado en un lab de HTB pero redactado profesionalmente
- [ ] **1 proyecto "completo"** — aunque sea pequeño, pero bien documentado
- [ ] **1 artículo de blog** — explicando algo que te costó aprender

> [!tip] No necesitas 20 cosas. Con 3-4 piezas bien pulidas ya tienes un portafolio sólido para mostrar.
